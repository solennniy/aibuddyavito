# SDD: сценарий запроса доступа

## Цель и контекст
Стажёр хочет запросить доступ к пространству своей команды. Контекст выбирается из тестового профиля и задачи; сведения берутся только из доступной этому пользователю тестовой инструкции.

## Поведение
1. Показать текущий этап, статус и следующий шаг.
2. На вопрос дать ответ по доступной инструкции с указанием источника; при отсутствии сведений сказать об этом и предложить обратиться к наставнику.
3. Подготовить заявку только для доступного ресурса. До отправки показать ресурс и запросить явное подтверждение.
4. Проверить права на сервере и вызвать адаптер имитации сервиса. При успехе сохранить возвращённые идентификатор и статус, показать их и следующий шаг. Статус заявки не равен факту выдачи доступа.
5. При отказе или сбое не сообщать об успехе. Показать понятную ошибку и допустимый следующий шаг. Повторный запрос не должен создавать дубликаты.

## Приёмочные проверки
- Пользователь видит только разрешённую инструкцию и может отправить разрешённую заявку после подтверждения.
- Отказ в доступе не раскрывает запрещённые сведения и не создаёт заявку.
- Ошибка интеграции не меняет статус на успешный; повтор и перезагрузка корректно отражают сохранённый результат.
- Отсутствующий источник не заменяется выдуманным ответом; пользователь видит путь к наставнику.

## Границы
Инструкция и интеграция синтетические. Актуальный контракт реализации описан в [спецификации P0](../specs/p0-contract.md).

## Опциональная модель

Сервер определяет намерение по вопросу и проверяет разрешения до подбора документов. В деморежиме он выбирает источник по правилам. В режиме с моделью она получает вопрос и разрешённые документы по выбранному намерению и возвращает идентификатор. Сервер проверяет идентификатор и выводит текст из локального источника. У модели отсутствует доступ к функциям изменения данных и прав. Вызов имитации выполняется после отдельного подтверждения через защищённую операцию API.
