# AI Buddy

Прототип для Hack&Change 2026. Стажёр видит план адаптации, изучает учебные материалы и проходит путь от вопроса о доступе до сохранённой заявки в имитации корпоративного сервиса.

## Запуск через Docker Compose

Нужен запущенный Docker Desktop или Docker с Compose. Скачайте ветку `main` через **Code → Download ZIP** либо клонируйте репозиторий. В корне проекта выполните:

```sh
docker compose up --build
```

Откройте <http://localhost:5173>. Для быстрого демо ключ и файл `.env` не требуются. SQLite хранится в томе `buddy-data`. Остановка и повторный запуск контейнеров сохраняют заявки и прогресс. Порт можно изменить через `WEB_PORT`.

## Локальный запуск

Нужны Python 3.11 и Node.js 24. Команды для Windows PowerShell из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-test.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```powershell
cd frontend
npm ci
npm run dev
```

На macOS или Linux используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`. Интерфейс доступен на <http://localhost:5173>, описание API — на <http://localhost:8000/docs>. Локальный файл данных — `data/aibuddy.sqlite3`. Версии зависимостей указаны в файлах `backend/requirements*.txt` и `frontend/package-lock.json`.

## Проверка сценария

1. Нажмите значок профиля и выберите Анну в переключателе тестовых пользователей. Пароли для демонстрации не нужны. Вернитесь в «Обзор».
2. Откройте «Сообщения» и спросите «Как получить доступ к пространству команды?». Раскройте «Источники» и нажмите «Создать заявку».
3. Введите причину, подготовьте черновик и подтвердите отправку отдельной кнопкой.
4. Проверьте номер заявки, статус «Отправлена» и следующий шаг. В разделе «Мои заявки» обновите страницу и убедитесь, что запись сохранилась.
5. Через страницу профиля переключитесь на Ивана. Его список содержит только его собственные заявки. Профиль наставника Марии показывает отправленные заявки закреплённых стажёров.
6. Для проверки повторной отправки в новой заявке добавьте `[fail-once]` к причине. Первое подтверждение вернёт демонстрационную ошибку, второе отправит тот же черновик.
7. В профиле Марии согласуйте заявку. Вернитесь в профиль Анны, откройте «Мои заявки» и нажмите «Демо: подтвердить выдачу доступа». После этого первая рабочая задача получает статус «Можно начать».
8. В «Сообщениях» напишите «Я познакомилась с командой». Нажмите «Подтвердить выполнение» и проверьте отметку в чек-листе и следующий шаг в переписке.

Учётные записи, база знаний и сервис заявок демонстрационные. Статус «Отправлена» означает, что учебный сервис принял заявку. Выдача доступа моделируется отдельным событием для уже отправленной заявки. Демонстрационная кнопка воспроизводит только событие тестового сервиса.

## Модель и источники

Режим по умолчанию работает без ключа. Сервер определяет намерение, выбирает учебную инструкцию среди разрешённых роли документов и формирует ответ с источником. Если инструкции нет, интерфейс предлагает уточнить вопрос.

Для проверки живой модели скопируйте `.env.example` в `.env`. Заполните `LLM_API_URL` (полный URL OpenAI-совместимого Chat Completions), `LLM_MODEL` (идентификатор у выбранного провайдера) и `LLM_API_KEY`. Передавайте проверяющим временный ключ отдельно от репозитория. Docker Compose читает локальный `.env`. После смены настроек выполните `docker compose up -d --force-recreate api`. При запуске через Uvicorn задайте эти переменные в окружении процесса. Модель формулирует ответ по разрешённому источнику, а сервер проверяет ссылку и опорную цитату. Статусы, подтверждение прогресса и отправка заявок обрабатывает сервер.

## Тесты и покрытие

В корне репозитория:

```powershell
.\.venv\Scripts\python.exe -m coverage run --source=backend --omit='*/tests/*' -m pytest backend/tests
.\.venv\Scripts\python.exe -m coverage report --precision=2 --show-missing --fail-under=80.01
.\.venv\Scripts\python.exe -m coverage xml
```

Из `frontend`:

```powershell
npm ci
npm run build
npm run test:coverage
npx playwright install chromium
$env:PYTHON = (Resolve-Path ..\.venv\Scripts\python.exe).Path
npm run test:e2e
```

На macOS или Linux перед последней командой задайте `export PYTHON="$(cd .. && pwd)/.venv/bin/python"`. Playwright поднимает отдельные экземпляры API и Vite на портах 8017 и 5177 и использует отдельную базу SQLite. Если установлен браузер Chromium или Edge, для локальной проверки можно указать абсолютный путь через `BROWSER_PATH`.

GitHub Actions запускает сборку, серверные тесты, Vitest с покрытием и браузерный сценарий. Отчёты выгружаются как артефакты запуска. Покрытие серверного и клиентского кода проверяется отдельными порогами.
